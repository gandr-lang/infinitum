# infinitum-changelog

Workflow tooling for [infinitum](https://github.com/gandr-lang/infinitum): generates `CHANGELOG.md` as the default branch will hold it.

A pull request lands as one squash commit whose subject is `<pull request title> (#<number>)`, so a changelog generated from a branch's own commits is never the changelog `main` generates after the merge. This binary removes that difference at the source.

## Use

Through the task, never directly:

```sh
mise run changelog --exclude-path CHANGELOG.md
```

`treefmt` calls it that way as the changelog formatter; the generated bytes go to `.git-cliff-output`, and the installing formatter replaces `CHANGELOG.md` only when they differ. Arguments are passed through to `git-cliff` unchanged.

## Inputs

| Input | Read from | Used for |
| ----- | --------- | -------- |
| event name | `GITHUB_EVENT_NAME` | choosing the rendering mode |
| source branch, checked-out ref | `GITHUB_HEAD_REF`, `GITHUB_REF_NAME` | naming the pull request on a forge run |
| branch, merge base, commit list | `git` | the commits a squash will replace |
| request state, number, title | `gh pr view` | the subject the squash will carry |

`main`, and any `push` or `merge_group` run, render plainly: the real squash commit is already present. Every other run renders `merge-base(origin/main, HEAD)..HEAD` with each branch commit skipped and one synthetic commit carrying the squash subject.

## Failures

Every failure is written to standard error as `error: <message>`, and nothing is generated on that path:

- **No open pull request** — including a merged or closed one for a reused branch: the run stops with `open the PR first, then regenerate`. Guessing a subject would write a changelog the merge contradicts.
- **A forge or Git command fails, or is not installed**: the failure names the program and carries its message.
- **The forge's answer lacks state, number or title**: refused rather than rendered from a partial answer.

```text
error: no open pull request for `scaffold` (state: MERGED): open the PR first, then regenerate
```

The ordering these failures imply is in `AGENTS.md` §changelog-ordering: open the pull request, regenerate, push; a retitle owes a regeneration.
